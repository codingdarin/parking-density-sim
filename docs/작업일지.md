### D7 — 지표(MetricsRecorder) + CSV export + 평시 출차 시뮬(최소)
- Core/Metrics: `RunMetrics`(비상 1건 입력+산출 평면 레코드) / `MetricsRecorder.FromEmergency`(가동률·유효 병렬성·봉투 대비 이탈 환산) / `CsvFormat`(InvariantCulture 서식, 파일 IO 없음) / `NormalOpsSim`(평시 출차 최소 — 통로 차량 인출, 시드 주입 System.Random)
- ConsoleSim: `batch`(데모 스윕 + 고정 시나리오 CSV 로더 → output/emergency_metrics.csv), `normal`(평시 데모) 명령 추가
- **유효 병렬성 실측**: makespan 대비 로봇 활동 틱 합 → EffectiveP(동시 가동 로봇 평균). 봉투는 p=RobotCount 기준으로 일반화, DeviationRatio 병기
- **정합 앵커 재현**: (레인1, d=100, 포켓 on, 로봇4) = 10.0분 → D6 본 구현 로그값 정확히 재현. 배치·평시 모두 2회 실행 바이트 동일(결정론). 회귀 test 5/5·sanity 통과
- **데모 스윕에서 로봇 대수 축 첫 관찰 (발표 서사 직접 증거)**: 1레인·포켓 on 기준 d=100에서 2대 12.75분 → 4대 10.00분 (**2배 증차에 −21.6%뿐**). EffectiveP 1.50 → 2.66 (4대 중 실효 2.66대만 동시 가동 — 병렬성 붕괴 실측). "장비를 더 사면 되지 않나"에 대한 데이터 답의 첫 조각
- **피드백 검토 결론(무조건 수용 X)**: ① 로봇 대수 축 승격 = 수용(강) — 단 대기소 4칸 하드코딩(EmergencyPlanner allHomes / ParkingLayoutBuilder depot 행) 일반화가 5대↑ 스윕의 선결 조건(depotY x=0..7에 8칸 수용 가능). ② D5 건너뛰고 D9 우선 = 조건부 수용 — "미룸"이지 "취소" 아님, 성공기준 1~3(Unity 데모)은 D9 후 발표 전 복귀 필수

### D9 선결 — 대기소 일반화 (로봇 대수 축 개방) + 로봇 대수 헤드라인 실측
> **방침(이 시점부터)**: 개발계획서는 현재 버전에서 **동결**. 이후 검토·발견은 계획서를 사후 정정하지 않고 작업일지에만 기록한다. **예측(계획서 봉투) vs 실측(작업일지)의 격차 자체가 발표 자료.** 코드 선결 조건(대기소 일반화 등)은 계획이 아니라 구현이므로 계획서 수정 없이 진행.

- **대기소 하드코딩(4칸) 제거**: `ParkingLayoutBuilder`가 대기소를 진입구 서쪽 열 전부(x=0..corridorStartX-1 = 기본 8칸)로 생성, `ParkingLot.DepotY`·`DepotCells`로 중앙화. `EmergencyPlanner`·`NormalOpsSim`은 하드코딩 배열 대신 `lot.DepotCells.Take(robotCount)` 사용(두 곳 재계산 드리프트 제거). RobotCount는 대기소 칸 수로 상한 클램프
- **4대 회귀·앵커 완전 보존**: test 5/5, sanity 통과, (레인1·d100·포켓·로봇4)=10.00분·하위 지표 전부 동일 (행동 보존 리팩터)
- **로봇 대수 축 실측 (레인1·d100·포켓 on, 시드0)** — 대기소 개방으로 처음 5대↑ 가능:

  | 로봇 | 확보(분) | 유효 병렬성 EffectiveP | 가동률 | 봉투(분) | 이탈배율 |
  |---|---|---|---|---|---|
  | 1대 | 17.0 | 0.87 | 86.8% | 43.3 | 0.39x |
  | 2대 | 12.8 | 1.50 | 74.9% | 21.7 | 0.59x |
  | 3대 | 11.1 | 2.13 | 71.0% | 14.4 | 0.77x |
  | 4대 | 10.0 | 2.66 | 66.6% | 10.8 | 0.92x |
  | 6대 | **8.3** | 3.79 | 63.1% | 7.2 | 1.15x |
  | 8대 | **8.3** | 4.50 | 56.3% | 5.4 | 1.52x |

  - **포화 실측**: 6대→8대(33% 증차)에 확보 시간 **0% 단축**. 통로가 유효 병렬성을 ~4.5대로 상한 → 8대 중 절반이 유휴(가동률 56%로 단조 하락). 1대→8대(8배)로도 17.0→8.3분(2배뿐)
  - **예측 vs 실측 격차 = 발표 핵심**: 봉투(이상적 선형 speedup)는 8대면 5.4분 예측, 실측 8.3분 — 이탈배율이 로봇 늘수록 0.39x→1.52x로 커짐(혼잡 손실이 병렬성 이득을 잠식). "장비 증설이 답"이라는 반문에 대한 데이터 답
  - **부수 관찰**: 8대로도 100m·1레인은 7분 미달(8.3분 ❌) — 증차로 넘을 수 없는 벽. 재시도(Attempts)는 로봇 수와 무관하게 9회 고정(경로 경합이 아니라 우선순위 순열 문제)

### D9 설계 결정 — 시드/배치 무작위성 (검토 후 기각)
- **피드백**: "시드 분산이 D9의 숨은 핵심. 전면 격자 전에 3레인·d100에서 시드 20개로 분산부터 측정. 크면 시드 독립축·최악배치 헤드라인, 작으면 5개로 격자."
- **객관 검토 — 전제가 현 모델에서 불성립(경험적 증명)**: 같은 조건에서 시드만 바꿔 실행 → clear_s 완전 동일(3레인 d100 pockets-off = 2262.5s×전 시드, 1레인 d100 pockets-on = 600.0s×전 시드). `ParkingLayoutBuilder`는 점유 레인을 가장자리부터 **빈틈없이 결정론적으로** 채우고 디스패치도 결정론이라 **비상 확보의 시드 분산은 구조적으로 0**. 20개 시드 실행은 "강건"이 아니라 "배치 자유도 부재"를 보게 됨 — 함정의 역방향
- **결정 = 배치 무작위성 도입 기각**. 근거: ① 밀도 단위가 처음부터 **레인 수(0~3)**(측정정의서 §2) — 연속 점유율이 아님. 레인은 "한 줄로 쭉" 채우는 운영 단위라 **만차가 정의에 부합하고 현실적**(갭 배치가 오히려 인위적) ② 배치 무작위 도입 = §2 밀도 정의 변경 → D0부터의 레인 기반 논증 전체 재검토(8일차 토대 변경 리스크 > 이득) ③ 로봇 대수 헤드라인(8대 유효 4.5대 상한, 봉투 5.4분 vs 실측 8.3분)이 이미 강력 — 새 축 리스크 불필요
- **수용**: 포켓 on/off 대조(T∝d² 기준선 격리) 유지. 최악값(평균 아님) 헤드라인 원칙 — **비상의 최악 = 최원단 화재**. 시드는 **평시 출차(무작위 요청 순서)에만** 실재 → 비상=결정론 / 평시=확률적 역할 분담
- **정직성 보강**: D9 비상 스윕에서 시드는 축이 아니라 고정값(0). CSV 시드 열은 남되 상수 — 없는 분산을 암시하지 않음. 시드 축은 평시 CSV 전용

### D9 본 배치 — 목적별 슬라이스 + 유휴 분해(원인 기반 태깅)
- **설계(피드백 수용)**: 전면 격자(레인4×d5×포켓2×로봇4 = 160셀) 대신 **목적별 OFAT 슬라이스**로. 축마다 물음이 다르니 통제변수 고정 → 각 슬라이스 = 발표 슬라이드 1장·변수 1개. `D9SliceRunner`:
  - 포켓 효과: 레인2·로봇4 고정, d{20..100}×포켓{off,on} [10셀]
  - 로봇 포화: 레인3·d100·포켓off·대기소8칸 고정, 로봇{1,2,4,8} [4셀]
  - 안전 도달 거리: 로봇4·포켓on 고정, 레인{0~3}×d{20..100} [20셀]
  - d=20m 간격 5점(선형/제곱 판별), 로봇 로그스케일(무릎), 7분 교차점 보강은 1차 후
- **유휴 분해(피드백 수용, 미구현이라 추가)**: 총 가동률만으론 "왜 노는가"를 못 가림 → 로봇-틱을 **active/주행대기/하차대기/완전유휴**로 분해(`ClearanceReport`). 1차 위치 기반 → **원인 기반 태깅**으로 정밀화: 대기 로봇의 **다음 진입 셀이 하차앵커면 하차대기(스필오버 포함), 아니면 순수 주행대기**. 대기 원인이 하차앵커 예약인지로 가름
- **핵심 발견 — 병목이 밀도 레짐에 따라 다른 종류다** (발표 뼈대):
  - **저밀도(레인1): 하차 병목 지배.** 포켓 off → 단일 메인 앵커, **8대는 계획 실패**(앵커 경합). 포켓 on → 병목을 travel→drop으로 이동시켜 확보 단축(15.0→10.0→8.3분)하나 **제거는 못함**: 원인기반 하차대기 4대 26.0%·8대 17.3%로 여전히 지배적 대기. (위치기반 1차 측정은 스필오버를 주행D로 오분류해 6.7%로 보였음). 처방 = 하차 지점 추가(포켓↑)·유예창 G 단축. **"포켓 더 늘리면?"이 데이터로 열림**
  - **고밀도(레인3): 접근 기하 병목.** 주행D·하차D 둘 다 바닥(≈1.0/1.5%), **유휴만 급증**(8대 10.7%). **8대(40.2분)가 4대(37.7분)보다 느림**. 만차 통로는 끝단부터만 접근 → 임계경로 구조적 직렬화 → 5대째부터 잉여 완전유휴. **포켓·증차 둘 다 무효** = 물리적 상한. (태깅 전후 동일 — 이미 확정, 손대지 않음)
  - **"증차하면 되지 않나"의 정밀한 답**: 저밀도는 하차 지점을 늘려야 하고(증차 무의미), 고밀도는 아예 불가능(접근 기하 상한). 단순 "증차 무효"보다 실무적
- **예측 채점 (방법론 서사)**: #2(고밀도 악화=혼잡 아닌 구조적 유휴) 대체로 적중. #1(저밀도 하차대기 지배)은 **위치기반 1차 측정에서 틀린 듯 보였으나(drop 6.7%) → 파고들어 off/on 대조 발견 → 원인기반 태깅에서 실은 적중(17~26%)**. **측정 방법(위치 vs 원인)이 결론을 뒤집은 사례** — 진단 지표 정의 자체가 발견. 틀린 듯한 예측이 태깅을 강제해 더 깊은 구조를 드러냄
- 회귀: test 5/5·sanity, ClearTick/Collisions 불변(태깅은 대기 분류만 변경). 한계: 포켓-top 셀은 통로 통과 경로이기도 해 드물게 통과 대기를 하차대기로 계수 가능(메인 앵커 x=0은 서쪽 끝단이라 깨끗)

### D9 — 하차 병목의 핀은 포켓이 아니라 G (포켓 개수·G 민감도 스윕)
- **뾰족한 물음**: 하차대기가 포켓 수로 계속 주는가 / G가 만드는 하한이 어디인가 (예/아니오로 카드가 바뀜)
- **포켓 개수 스윕** (레인1·d100·로봇4, 균등분산 1/2/4/8): 확보 12.8→11.4→8.7→6.9분(8까지 계속 감소, 4에서 포화 안 함). 하차대기 21.2/24.2/22.1/18.9% — **포켓 1~8 내내 ~20% 불변**. 예측(단조감소·4포화) **둘 다 틀림** → 발견: **포켓은 이동(왕복)만 줄이고 하차대기 비율은 못 건드림**. 직전 "포켓이 하차 병목 완화" 헤드라인 **정정** — 포켓은 병목을 완화가 아니라 **비껴감**
- **G 민감도** (레인1·d100·로봇4·포켓4, G 6/12/18/24): 하차대기 12.7/22.1/28.5/33.0% — **G에 단조 비례**. 확보 7.5/8.7/11.4/13.5분, 유효p 3.34→1.98. 전 G에서 collisions=0. 예측(하차대기∝G) **적중** → **하차 병목의 핀 = G 확정**
- **처방 분리 확정 (핵심)**: **포켓 → 이동(travel), G → 하차 병목. 두 레버가 직교.** G 12→6이면 확보 −14%·하차대기 −9%p (충돌 0)
- 한계/이월: G<6 안전 하한(D6 체이닝 갇힘 버그 재발 여부)은 미탐침 — 카드는 이미 섰으므로 타임박스상 보류. 기본 G 변경은 별도 결정
- 예측 채점: 포켓 스윕 **오답**이 "포켓≠하차병목"을 드러내고, G 스윕 **적중**이 핀을 확정. 오답→발견·적중→확정 둘 다 수확 (측정정의서 밖 진단 축이지만 처방을 가르므로 결정에 쓰임)

### D9 — 레짐 경계 정량화 + 안전 도달 거리 (reach 슬라이스, 로봇4·포켓on)
