## 0. D0 — 시작 전 반나절 (필수 선행)

### 0-1. 봉투 뒷면 계산 (D0 재검증 완료)

상수: 1셀 = 2.5m, 차 1대 = 1×2셀, 통로 3셀 × 100m, 진입구 1개, 로봇 4대, 속도 1 m/s(셀당 2.5초), 적치 구역 = 진입구 밖 d_s = 15m, 부서공간 β = 10m.

**재검증에서 v6까지의 가정 하나가 깨졌다 — "왕복 고정 75초"는 성립하지 않는다.** 적치 구역이 진입구 쪽에 있으므로 왕복 거리는 차량 위치에 비례한다. 옮길 차량 수 N과 평균 왕복이 **둘 다 화재 위치 d에 비례 → T는 d의 이차 함수**:

> N = 레인 수 × (d+β)/5m,   T = N × ((d+β) + 2·d_s) ÷ p  [초, 1 m/s 기준]

**① 매트릭스 (p=4 완전 병렬 상한, β=10m, d_s=15m):**

| 점유 레인 (α, 500면 기준) | 화재 20m | 화재 40m | 화재 100m (최원단 = 최악) |
|---|---|---|---|
| 3레인 (+60대, +12%) | 4.5분 ✅ | 10분 ❌ | 32.5분 ❌ |
| 2레인 (+40대, +8%) | 3.0분 ✅ | 6.7분 ⚠️ | 21.7분 ❌ |
| 1레인 (+20대, +4%) | 1.5분 ✅ | 3.3분 ✅ | 10.8분 ❌ |

**② 유효 병렬성 p — 점유율의 함수, 봉투로 확정 불가:** 점유율이 높을수록 로봇 자신의 통행로도 사라진다. 단 직렬화(p=1) 가정은 과도함 — 비워진 구간은 폭 3셀이라 교행 가능하고, 프런티어에서 레인당 1대씩 최대 3대 동시 인출 + 파이프라이닝 여지. 추정: 3레인 p≈1~3, 2레인 p≈2~3, 1레인 p≈4. 실측은 시뮬레이션(로봇 가동률에서 도출).

**③ 안전 도달 거리 (7분 역산, (d+10)(d+40) ≤ 2100p ÷ 레인 수):**

| 점유 레인 | p 추정 | 안전 도달 거리 | p=4 상한 | (참고) v6 추정 |
|---|---|---|---|---|
| 3레인 | 1~3 | **5~23m** | 30m | 9~37m |
| 2레인 | 2~3 | **23~33m** | 41m | 28~56m |
| 1레인 | ≈4 | **≈68m** | 68m | 112m (전 구간) |

**결론과 설계 반영:**
- 확보 시간은 화재 위치의 함수 — **위치별 곡선**으로 다룬다. "전체 통로 확보"는 최원단 화재의 특수경우 → "확보 구간 정책" 축 없음.
- **v6 헤드라인 "1레인만 전 구간 안전" 폐기.** 이차 성장 때문에 **어떤 점유 수준도 전 구간(100m)을 커버하지 못한다** (진입구 1개 + 적치 1개소 기준). 잠정 헤드라인: "1레인 점유도 진입구 ~68m까지만 안전. 전 구간 커버는 복수 진입구 또는 복수 적치 구역 없이는 불가." — 완화 수단이 점유율 조절만이 아니라 **적치 구역 배치**라는 설계 변수로 확장됨 (기본 실험은 1개소 고정, 복수 적치는 한계 절에 기록).
- 독립변수: **① 점유 레인 수(0~3) ② 화재 위치 ③ 로봇 대수** (+ 민감도: β, d_s, 셀당 초, 임계값 / 시드). **적치 용량 S는 산출물**: S_필요 = N. 예: 3레인 최원단 → 60대 ≈ 750㎡ — 이 규모 공터의 존재 자체가 강한 가정 (한계 절 명시).
- **시뮬레이터의 존재 이유**: 봉투는 간섭을 무시한 이차 모델 — 실측 곡선이 혼잡·병렬성 붕괴로 이차 예측에서 이탈하는 지점(변곡점)과 p 실측이 시뮬레이션 고유의 산출물.
- 발표 서사: "로봇을 늘리면 빨라져야 하지만, 통로를 채우면 로봇이 지나갈 길도 사라진다. 곡선이 꺾이는 지점은 시뮬레이션 없이 알 수 없다."

### 0-2. 측정 정의서 작성 (`docs/측정정의서.md`, 1페이지)

| 항목 | 초안 정의 |
|---|---|

| 확보 완료 | 확보 구간 전체에 **폭 3셀 연속 빈 상태** 달성 최초 틱 |
| 측정 시작 | 화재 이벤트 발생 틱 (= 감지 시각) |
| 시간 예산 | 성공 조건: 확보 완료 ≤ 신고접수 + 7분 (소방청 골든타임). 감지=신고 동시 보수 가정, 리드타임은 안전 여유로만 |
| **대표값 집계** | **화재 위치를 스윕해 위치별 확보시간 곡선(분포 전체)을 기본으로 하고, 최원단(최악값)을 헤드라인 수치로 병기.** "불이 마침 입구 근처에서 났다면"을 전제하지 않음 |
| 민감도 축 | 임계값 5~9분 스윕 (지역별 실측 도착시간). 기준값은 7분 고정, 지역 편차는 민감도로만 (윤리적 서술 주의) |
| 밀도 | 통로 점유율 = 점유 레인 수 기준. 수용 대수(α) 절대값 병기 |
| 회전반경 10m | 판정 제외, 제외 사실 명시 (부서·활동 공간은 β로 부분 반영) |
| 시간 단위 | 틱 기록, 초 환산 계수는 표시·분석 단계 적용 |

### 0-3. 격자·레이아웃 확정

- 1셀 = 2.5m 정사각형, 차 1대 = 1×2셀, 통로 7m → 3셀(7.5m) 올림.
- 통로 위 주차 방향: **통로와 평행** — 1레인 단위 점유 + AGV 이동 축 정렬(회전 최소화).
- 1×2 강체 이동: 방향 정렬로 회전 최소화, 회전은 교차로 2×2 클리어런스에서만. 폴백: 이동 1셀 추상화 + 폭·수용 판정만 실셀.
- **진입구 1개 가정 (보수적)**: 최악값 100m는 "진입구 1개 + 통로 끝 화재" 전제. 복수 진입구 단지에서는 최원단 거리가 절반 이하로 감소하고 양방향 확보로 병렬성도 상승 → 본 결과는 안전 측. (단, 이 가정은 소방차 진입 경로에 대한 것 — 로봇의 통로 반대쪽 끝 접근은 내부 순환로 경유로 별개)
- **임시 적치 구역 (EmergencyStagingArea) — 레이아웃 필수 요소**:
  - 위치: 단지 내 비주차 공간(입구 광장, 공터 등), **단 소방 동선과 겹치지 않는 곳**
  - 용량 S (셀 수), 통로 진입구로부터의 거리 d_s — d_s가 왕복 시간을 결정
  - 근거: 만차 전제(통로 주차의 존재 이유) 하에서 빈 주차면은 최악 시나리오에 존재하지 않음 → 재배치 목적지는 도면에 명시된 전용 공간이어야 함. 실제 성능위주설계에서도 비상 대피 공간은 도면 요소

### 0-4. 재배치 목적지 규칙 (D6 선행 결정)

- **접근 순서는 규칙이 아니라 물리 제약**: 3레인 완전 점유 시 통로에 주행 레인이 없어 확보 구간의 **끝단부터만** 접근 가능. 1~2레인 점유 시엔 빈 레인으로 접근 가능.
- **목적지 = 적치 구역 단일화.** v4의 "화재 반대편 빈 셀 우선" 규칙은 폐기 — ① 만차 전제상 빈 주차면이 최악 시나리오에 존재하지 않고(α의 존재 근거와 상호 배제), ② "화재 반대편" = 화재 너머라 불 쪽으로 차를 옮기고 반대편 소방 접근을 막는 결함이 있었음.
- **S 부족 시 = "확보 실패 + 필요 S 기록"** — 단순 실패가 아니라 "이 점유율엔 이만큼의 적치 공간이 필요하다"는 설계 요구량 데이터가 됨. 고밀도 칸이 전부 ❌로 무의미해지는 문제 해소 (S 기본값은 넉넉하게 두고 필요량을 산출물로 기록).
- **한계 절에 명시**: 실제 운영에선 그 시점의 빈 주차면도 활용 가능 → 본 결과는 보수적(안전 측).
- D6 전 콘솔에서 시나리오 1개 예행 (D4 여력 시).

## 1. 목표와 성공 기준

### 성공 기준 (데모 시나리오)
1. 점유 레인 수를 조작하고 시뮬레이션 시작
2. **통로 임의 지점** 화재 클릭 → 전 로봇 확보 모드 → 확보 시간 + 7분 판정 표시
3. 수동 모드: 심사자가 직접 로봇을 조작해 통로를 열어봄 → 자동 대비 열세 체감
4. 배치 실험으로 **점유율별 안전 도달 거리 곡선** (점유 레인별 위치↔확보시간 다중 곡선 + 7분 임계선) 생성 — **봉투 예측선(이차 모델)을 함께 그려 변곡점(병렬성 붕괴 지점)을 대비시킴**

### 범위 우선순위

| 순위 | 항목 |
|------|------|
| **P0 (필수)** | 격자 맵, 다중 로봇 시공간 A*+예약 테이블(적대적 테스트 5종 — "해 없음 → 확보 실패 종료" 포함), 비상 이벤트(**화재 위치·β 파라미터**), 확보 시간 측정 + 7분 판정 |
| **P1 (중요)** | 파라미터 UI, 수동/자동 비교 모드, 배치 실험(**화재 위치 스윕 축 포함**) + 안전 도달 거리 곡선, 평시 출차 시뮬레이션, 고정 데모 시나리오 CSV, 콘솔 교착 데모(예약 off) |
| **P2 (여유 시)** | NavMesh 비교군 영상(보너스), 자동 리포트, 속도 민감도, 연출, asmdef 추가 |

## 2. 아키텍처 개요

```
┌─ Core/ (순수 C#, Unity 비의존 — 콘솔에서 먼저 개발·검증) ──┐
│  GridMap          셀 상태 (통로/주차면/진입로/장애물)        │
│  ParkingLayout    레이아웃(적치 구역 포함) + 점유 배치 생성   │
│  SpaceTimeAStar   (x,y,t) 탐색 + ReservationTable         │
│  TaskDispatcher   출차 요청 / 비상 재배치 작업 할당           │
│  EmergencyPlanner 화재 위치(입력) → 확보 구간 → 재배치 계획   │
│  MetricsRecorder  수용대수·출차시간·확보시간·가동률·7분판정    │
│  TextRenderer     콘솔 텍스트 시각화 (t별 격자 상태 출력)     │
└──────────────────────────────────────────────────────────┘
┌─ ConsoleSim/ (.NET 콘솔 — ParkingSim의 형제 디렉터리) ──────┐
│  Core/ 소스를 상대 경로 와일드카드로 포함                     │
│  적대적 테스트 5종 + 시나리오 러너 — D1~D4의 주 작업 환경     │
└──────────────────────────────────────────────────────────┘
┌─ Unity Layer (D5부터) ────────────────────────────────────┐
│  SimulationRunner / AgvView·CarView (코드 생성 프리미티브)   │
│  ParameterPanel / ManualControl / ChartView / BatchRunner  │
└──────────────────────────────────────────────────────────┘
```

- **Unity 에디터 의존 최소화**: 오브젝트는 전부 코드 생성(`GameObject.CreatePrimitive`), 카메라도 코드 세팅, 씬엔 부트스트랩 1개.
- **Core 순수성 강제 = ConsoleSim 빌드**: Core가 UnityEngine을 참조하면 콘솔 빌드가 실패하므로 컴파일 타임 가드는 이미 존재. **asmdef는 D5에 넣지 않고 P2로 연기** (참조 설정 꼬임 리스크 > 당장의 이득).
- **bin/obj 주의**: ConsoleSim은 UnityProject 밖 형제 디렉터리 유지 — 빌드 산출물이 Assets에 들어가면 Unity 임포트 에러. 구조 변경 시 의식할 것.
- 시드 고정 `System.Random`만 사용.

## 4. 주요 기술 결정 사항

| 항목 | 결정 | 이유 |
|------|------|------|
| 격자 | 1셀=2.5m, 차=1×2셀, 통로=3셀, 통로 주차는 평행 | 1레인 단위 점유 + 회전 최소화 |
| 성공 임계값 | 골든타임 7분 고정, 감지=신고 보수 가정. 5~9분은 민감도로만 | 소방청 공식 기준 (출처 검증 완료) |
| **집계 규칙** | **화재 위치 스윕 → 위치별 곡선 + 최악값 헤드라인. 확보 구간 정책 축은 삭제(위치 스윕에 포섭)** | 안전 논증에서 화재 위치를 전제할 수 없음. "전체 확보" ≡ 최원단 화재 |
| **확보 구간** | 진입구→화재지점**+β** (기본 10m, 끝단 클램프), β 파라미터화 | 소방 부서·활동 공간 반영, 결과 보수화 |
| **병렬성** | 봉투 계산(이차 모델)은 상한으로만 사용. 유효 병렬성은 시뮬레이션 실측(로봇 가동률에서 도출), 예측 이탈 지점이 D9 핵심 산출 | 봉투 모델을 재현할 거면 시뮬레이터가 불필요 — 이탈 지점이 존재 이유 |
| 재배치 목적지 | **적치 구역 단일화** (1급 레이아웃 요소, 소방 동선 밖, 거리 d_s 파라미터). S는 산출물(조건별 필요량 기록) | 만차 전제와 빈 셀 목적지의 모순 해소, 규칙 단순화 |
| 경로 계획 | 시공간 A* + 예약 테이블 → 폴백: Prioritized Planning | 3~4대에서 품질 차이 작음 |
| 개발 순서 | 콘솔 우선, Unity는 코드 생성 위주, asmdef는 P2 | ConsoleSim 빌드가 순수성 가드 역할 |
| 비교군 | 콘솔 교착 데모(예약 off) — "무조정 독립 계획" 명명. NavMesh는 P2 보너스 | 같은 코어에서 예약만 제거한 통제된 비교 |
| 랜덤성 / 재현성 | 시드 고정 System.Random, 실험=랜덤·시연=고정 CSV | — |
| 시간 | 틱 기록, 초 환산은 표시 단계 | 속도 민감도 = 계수 변경 |
