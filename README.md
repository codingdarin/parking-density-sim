# parking-density-sim

로봇 주차장이 평상시 통로를 점유해 얻는 추가 수용량과, 비상시 통로 확보에 드는 시간을 비교하는 시뮬레이터입니다.

핵심 질문은 하나입니다.

> 비상시 규정 폭을 7분 안에 확보할 수 있다면, 평상시 통로 점유를 어디까지 허용할 수 있는가?

## 현재 Model V2

- 차량은 소멸하지 않고 유한 적치면을 계속 점유합니다.
- 차량 pose는 1×2셀 가로/세로이며 운반 중 회전·충돌을 검사합니다.
- 운송 유닛 1~8조, 시공간 A* 정점/엣지 예약, 유한 적치 배정을 지원합니다.
- 입구와 화재 위치에서 폭 3셀 접근 후보를 상위 K개까지 자동 생성하고,
  후보별 물리 개통시간을 비교합니다.
- 적치 슬롯별 토지 성격을 기존 비주차 포장·주차 가능 부지 전용·미확인으로
  구분하고, 상시 전용한 전체 적치면의 기회비용을 순수용량에서 차감합니다.
- 소형 문제는 exact 오라클과 비교하고, 운영 규모는 bounded 후보의 물리 유효 상한으로 보고합니다.
- Core는 Unity 비의존 순수 C#이며 ConsoleSim과 Unity가 같은 구현을 사용합니다.

## 핵심 결과

아래 표는 폭3×100m 통로, 이동1m/s, pickup/drop 각1틱, 운송 유닛4조의
**미보정 알고리즘 기준선**입니다. 단순 `틱×2.5초`는 현실 성능값이 아닙니다.

| 점유 레인 | 추가 수용량 | 7분 안전 도달거리 | 100m 확보시간 |
|---:|---:|---:|---:|
| 1 | +20대 (+4%) | 55m | 329틱 / 13.7분 |
| 2 | +40대 (+8%) | 30m | 716틱 / 29.8분 |
| 3 | +60대 (+12%) | 20m | 1,190틱 / 49.6분 |

미보정 기준에서는 1레인·100m 포켓14가 160틱(400초)으로 7분을
만족합니다. 다만 포켓의 주차 기회비용을 빼면 순증가 수용량은
+6대(+1.2%)로 감소합니다.

[Stanley Robotics 공개 기술사양](https://www.stanley-robotics.com/wp-content/uploads/2022/07/stanley-robotics-robot-spec.pdf)의
차량 취득90초·해제60초를 적용하면 결론이 달라집니다.

| 이동속도 | 상시개방 | 전면5대 | 상부2대 | 자동 하부3대 | 포켓14·20대 |
|---:|---:|---:|---:|---:|---:|
| 1m/s | 0초 | 432.5초(실패) | 242.5초 | 235.0초 | 1,102.5초(실패) |
| 2m/s | 0초 | 366.2초 | 196.2초 | 192.5초 | 977.5초(실패) |
| 3m/s(공개 최대) | 0초 | 344.2초 | 180.8초 | 178.3초 | 901.7초(실패) |

차량20대/4조는 pickup+drop 서비스만 최소 750초이므로 이동속도와 무관하게
7분을 넘습니다. 따라서 160틱 통과는 알고리즘 회귀값으로만 유지합니다.
같은 지상형 맵에서는 자동 하부가 전면 재배치보다 45.7~48.2% 빠르고,
차량 수가 더 적은 상부보다도 2.5~7.5초 빠릅니다.

## 실행

```powershell
dotnet build ConsoleSim
$env:DOTNET_ROLL_FORWARD='Major'
dotnet run --project ConsoleSim --no-build -- v2test
```

주요 명령:

- `v2report` — 핵심 조건을 재계산해 `output/v2_report.md` 생성
- `v2final` — 동일 지상형 맵의 4정책×현실속도 최종 비교 CSV 생성
- `v2finegrid` — 레인×5m 전 거리 60점 및 시간 민감도 CSV 생성
- `v2orobots` — 운영 규모 로봇1/2/4/8조 비교
- `v2pockets` — 포켓 개수 스윕
- `v2pocketlayouts` — 포켓 위치 오프셋 민감도

Unity는 `ParkingSim` 프로젝트를 열고 Play합니다.

- 바닥 셀 클릭: 해당 셀을 화재 위치로 삼아 폭 3셀 접근 후보를 자동 생성하고
  물리 개통시간이 가장 짧은 경로로 즉시 재계획
- 청록색: 선택 경로, 파란색: 선택되지 않은 상위 후보, 빨간색: 화재 위치
- 숫자키 `1`: 기본 화재 위치의 전면 5대 재배치 기준선
- 숫자키 `2`: 현재 화재 위치의 자동 핵심경로
- HUD 시간은 Stanley 공개사양의 1m/s·pickup 90초·release 60초 참조 프로파일
  기준이며, 후보 생성 실패 시 기존의 성공한 재생 화면을 유지하고 실패 이유를 표시

## 검증

```powershell
dotnet run --project ConsoleSim --no-build -- v2test
```

현재 V2 타당성 게이트는 53종이며 차량 보존, 유한 적치, 회전, 추종/스왑,
exact 격차, 운영 통로·포켓 위치 강건성, 자동 폭 3셀 접근경로의 실패 계약과
결정론, 적치 토지 성격별 순이득 회계, 공개사양 현실 시간 보정을 포함합니다.

## 구조

- `ParkingSim/Assets/Scripts/Core/V2/` — Unity 비의존 Model V2 Core
- `ParkingSim/Assets/Scripts/Runtime/` — Unity 코드 생성 재생기
- `ConsoleSim/Scenarios/` — 실험·CSV·자동 리포트 러너
- `docs/작업일지.md` — 사전 예측, 실측, 오답과 발견
- `docs/측정정의서.md` — 수치·집계 기준

## 한계

- 합성 격자이며 실제 아파트 도면을 아직 사용하지 않습니다.
- 연속 공간의 차량 회전 swept volume, 실제 센서·제어·가감속은 모델 밖입니다.
- 절대시간은 셀당 시간 가정에 종속됩니다.
- 운영 규모 결과는 후보8의 실행 가능한 상한이지 전역 최적값 증명이 아닙니다.
- 실제 적용에는 성능위주설계 검토와 실증이 필요합니다.
